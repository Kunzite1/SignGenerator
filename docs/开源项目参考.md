# 开源项目参考与实现取舍

本文记录第一版固件实际查阅的项目、借鉴点和已知差异，便于后续定位 DAC、DMA、频率计算、按键和 OLED 问题。审查日期为 2026-09-08。本项目未直接复制下列项目的业务代码，而是依据 STM32 HAL 接口自行实现。

## 主要参考

### STM32CubeF1 官方 DAC 示例

- 项目：[DAC_SignalsGeneration](https://github.com/STMicroelectronics/STM32CubeF1/tree/master/Projects/STM3210C_EVAL/Examples/DAC/DAC_SignalsGeneration)
- 用途：核对 F1 系列的 `PA4/DAC_OUT1`、TIM6 更新事件 TRGO、DMA2 Channel 3、半字循环 DMA 和 DAC 输出缓冲配置。
- 本项目取舍：沿用“先启动 DAC DMA，再启动 TIM6”的顺序；官方例程只有三角波和阶梯波，波形业务代码自行实现。

### SimpleSignalGenerator_BaseOnStm32HAL

- 项目：[Gitee 仓库](https://gitee.com/chenjjian/SimpleSignalGenerator_BaseOnStm32HAL)，审查提交 `2b6dfa4`，GPL-2.0。
- 用途：参考 [`bll_signal_generator.c`](https://gitee.com/chenjjian/SimpleSignalGenerator_BaseOnStm32HAL/blob/2b6dfa43e82261083ebd1b16a7e552c7f930c84c/Project/BLL/bll_signal_generator.c) 的 256 点查表、四种波形和设置/驱动分层。
- 已知问题：其 F103ZET6 分支未实测；频率计算遗漏 `ARR + 1`，0 Hz 缺少保护，显示值也不是定时器可实现的实际频率。本项目不照搬这些实现。

### EMBO

- 项目：[parezj/EMBO](https://github.com/parezj/EMBO/tree/df9907b74a75586942d43259268aa375cc25c5b5)，MIT。
- 用途：参考 [`sgen.c`](https://github.com/parezj/EMBO/blob/df9907b74a75586942d43259268aa375cc25c5b5/src/firmware/src/app/sgen/sgen.c) 的波形生成和安全重配置流程，以及 [`util.c`](https://github.com/parezj/EMBO/blob/df9907b74a75586942d43259268aa375cc25c5b5/src/firmware/src/util/util.c) 的 PSC/ARR 搜索与实际频率计算。
- 本项目取舍：不引入其 FreeRTOS、SCPI 和 Qt 上位机框架；固定使用较小的 256×`uint16_t` 缓冲区。

### stm32_functgen

- 项目：[angst7/stm32_functgen](https://github.com/angst7/stm32_functgen/tree/e142b51e4a9a2bfc9fa5d4bed017f30a9b8dcb84)，BSD-2-Clause。
- 用途：了解固定采样率、相位累加和 DMA 半缓冲更新方案。
- 不采用原因：目标为带 FPU 的 STM32F405，约 40 KiB 的 DAC 缓冲几乎耗尽 F103RCT6 的 48 KiB SRAM，且旧 HAL 启动顺序和数值钳位存在风险。可在高频波形质量不足时再参考相位累加思路。

## 显示与交互参考

- [BluePillWaveGen](https://github.com/BojanSof/BluePillWaveGen)：参考单页状态显示和波形循环交互。其输出为 GPIO R-2R，且仓库没有明确许可证，因此不复制源码。
- [立创开源 STM32F103RCT6 信号发生器](https://oshwhub.com/Fangbrbr/stm32-kai-fa-ban)：芯片型号与本项目一致，可对照四键和 OLED 的操作效果；工程采用旧 StdPeriph/Keil，附件还包含授权不同的第三方代码，仅作现象和界面参考。
- [afiskon/stm32-ssd1306](https://github.com/afiskon/stm32-ssd1306)：参考 SSD1306 初始化命令和 HAL I2C 通信方式，许可证为 MIT。第一版仅实现项目需要的 ASCII 状态页。

## 本项目第一版基线

- 数据链路：TIM6 TRGO → DAC1 Channel 1（PA4）→ DMA2 Channel 3 循环传输。
- 波形：正弦波、方波、三角波和锯齿波；根据频率自动使用 256、128 或 64 点，并将 12 位码值限制在 `256..3839`，避免输出缓冲在电源轨附近削顶。
- 频率：限制为 1 Hz～10 kHz，并按
  `f_out = TIM6CLK / ((PSC + 1) × (ARR + 1) × N)`
  计算和显示实际频率，其中 `N` 为当前采样点数。采样率限制为不超过 1 MS/s。
- 输入：PB12 启停、PB13 换波、PB14 减频、PB15 加频；低电平有效，非阻塞消抖。
- 显示：SSD1306 I2C 地址默认 `0x3C`，显示波形、设定频率、实际频率和运行状态。

采样点分档为：1～3906 Hz 使用 256 点，3907～7812 Hz 使用 128 点，7813～10000 Hz 使用 64 点。当前 72 MHz TIM6 时钟下可用以下数值核对串口、OLED 和示波器：

| 设定频率 | 点数 `N` | `PSC` | `ARR` | 计算实际频率 |
|---:|---:|---:|---:|---:|
| 1 Hz | 256 | 4 | 56249 | 1.000 Hz |
| 1000 Hz | 256 | 0 | 280 | 1000.890 Hz |
| 10000 Hz | 64 | 0 | 112 | 9955.752 Hz |

## 排查索引

- 没有模拟输出或 DMA 不运行：先对照 STM32CubeF1 官方示例的 DMA 通道、数据宽度、循环模式和启动顺序。
- 频率偏差或某档无法实现：检查 `PSC/ARR` 的 `+1`、APB1 定时器时钟、动态采样点数以及显示值是否使用计算后的实际频率；再对照 EMBO 的算法。
- 高频波形失真：先确认代码已按 256/128/64 点分档且采样率不超过 1 MS/s，再检查 DAC 负载和示波器探头；不能直接套用 EMBO 的高采样率上限。
- OLED 无显示：先扫描 `0x3C/0x3D`，检查上拉和供电，再核对 SSD1306 初始化序列。
- 按键连击或无响应：确认输入上拉、低有效接线以及扫描周期，不要在按键处理函数中阻塞等待释放。
